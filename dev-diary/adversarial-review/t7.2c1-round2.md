### Read, re-measured with my own stand-ins

Ordering. My probe built six rows, two at `version_seq` 1, three at 2, one at 3, and shuffled
them 500 times. Every run returned `(version_seq, commit_id)` order `e1, e2, e3, e4, e5, e6`.
The map in `collapseCommitHistory` cannot leak order because the final sort is total. A
`version_seq` tie resolves on the unique `commit_id`.

Collapse. My probe measured zero, one, and several action rows. A commit with no action row kept
empty action, author, and instruction. A commit with one action row took it. A commit with
several rows picked the prompt-bearing row, then the newest `action_created_at_ms`, then the
greatest `event_key`. I placed the expected winner in the middle and last to remove positional
bias. Every run agreed.

Full tie. The `actions` view applies `FINAL` over `ORDER BY (dub_id, commit_id, event_key)`.
Two rows for one commit cannot share an `event_key`, because that tuple is the dedup key. So the
three-step rule is total and the result is deterministic.

created_at. My probe pinned `0` to `1970-01-01T00:00:00Z`, `1788825600000` to
`2026-09-08T00:00:00Z`, `1788825601500` to `2026-09-08T00:00:01.5Z`, and `1788825602789` to
`2026-09-08T00:00:02.789Z`. The statement selects Unix milliseconds from a DateTime64 with no
zone, so the instant is absolute and Go formats it in UTC.

Parameter binding. My probe captured one request. `param_dub_id` equalled `probe-dub-id`. The
query equalled `selectCommitHistory`. The query text did not contain the dub id. Both subqueries
bind `{dub_id:String}`, so no caller value reaches the statement text.

### Branch cost decision, re-measured

I searched every INSERT into `charges_raw`. One writer exists. `chargeInsert` at
`internal/ledger/takes.go:19` is used only by `RecordTake` at `takes.go:93`. `TakeAttempt.rows()`
rejects an empty `CommitID` at `takes.go:123`. `chargeRows()` copies `a.CommitID` into every
charge row at `takes.go:208`. No other INSERT into `charges_raw` exists in `internal` or `cmd`.
`cost.Charge` carries no commit field. So no shipped writer can produce an unattributed charge,
and the rename to `AttributedCostUSD` is the honest fix.

No caller names the old branch-view field. The only `CostUSD` in Go is the unexported
`branchCostRow.CostUSD` decode alias at `history.go:100`. No file under `web/src` and no root
document names it. The remaining `BranchView.CostUSD` strings sit in closed phase records.

The doc comments state the exclusion accurately. `BranchView` and `CompareBranches` say the sum
excludes a charge row with an empty `commit_id`. `selectBranchCost` joins `charges` on
`ch.commit_id = a.commit_id`, and every ancestry `commit_id` is non-empty, so the exclusion
holds.
