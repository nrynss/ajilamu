# T4.6 contract change proposal

## Blocker

T4.6 cannot persist peaks within `internal/ledger/peaks.go` alone.

`sql/schema.sql` already declares `takes_raw.peaks Array(UInt8)`. The API contract already
declares `api.Take.Peaks []int`. The T4.2 write seam omits peaks from every writer shape.

| Where | What | Pin | Mutation |
| --- | --- | --- | --- |
| `internal/ledger/takes.go:16` | `takeInsert` omits the `peaks` column | Capture JSONEachRow from `Client.RecordTake` and require 64 to 128 numeric peaks | Reverting the column preserves a default empty array instead of the rendered waveform |
| `internal/ledger/takes.go:22` | `TakeAttempt` cannot carry the `[]uint8` result from `assemble.Peaks` | Compile a caller that provides rendered peaks to `RecordTake` | Reverting the field leaves no owned data path into ClickHouse |
| `internal/ledger/takes.go:41` | `takeRow` omits a `[]uint8` JSON field | Capture the take row and require UInt8 values from 0 through 255 | Reverting the row field drops the waveform before enqueueing |
| `internal/ledger/takes_test.go` | T4.2 has no regression pin for the peak column | The capture test requires stored peaks and rejects lengths outside 64 through 128 | Reverting validation permits malformed vectors or silent default arrays |

## Required ownership change

Create T4.2a after T4.2's approved commit. It owns `internal/ledger/takes.go` and
`internal/ledger/takes_test.go`. It adds an optional `Peaks []uint8` to `TakeAttempt`, validates
the empty or 64 through 128 contract, and includes `peaks` in `takeInsert` and `takeRow`.

T4.6 remains blocked until T4.2a lands. T4.6 then owns the ledger-side validation and wire
mapping in `internal/ledger/peaks.go`. No audio file read belongs in ledger code.
