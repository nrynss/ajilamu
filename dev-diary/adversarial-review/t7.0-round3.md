**Finding 4, closed.** `.gitignore` line 9 now reads `/data/`. With the directory present,

matches even when the directory is absent.

## Observations, Not Findings

These are real behaviours I measured. Each one sits outside T7.0's owned paths, so I record
it for the owning task rather than filing it here.

- `HEAD /api/dubs` returned 405. The mux pattern `GET /api/dubs` accepts HEAD, then
  `IndexHandler` rejects any method other than GET. That handler lives in
  `internal/api/index.go`, which T7.4 owns.
- `POST /api/config` with only `voice_key` returned 400 `Settings could not be read.` The
  same held for `translation_key` alone. `singleFormValue` in `internal/api/index.go`
  requires both fields to be present. The settings page always sends both, so the browser
  path works. T7.4 owns that handler.
- Wrong-method API requests return 404 rather than 405 with an `Allow` header. Round 2 asked
  for 404 or 405, so the seam meets its own bar. A future task may prefer 405.
- `GET /API/healthz` returned the SPA document with 200. HTTP paths are case sensitive, so
  that is a client route rather than an API call. T7.0a owns what the SPA does with it.
- A second SIGTERM during the drain window does nothing, because `signal.NotifyContext`
  keeps the handler installed until `stop` runs. An orchestrator that escalates to SIGKILL
  is unaffected.

## Required Remediation Direction

Flush the ledger even when the HTTP drain hits its bound, and log the pending count in that
case. Give the drain and the flush separate budgets inside `shutdownTimeout`. Make a missing
frontend build fail the boot under `ENV=production`, or make health report the degraded
state. Let a setting name the frontend root. Have the readiness route observe ClickHouse
rather than the environment. Install no config callback until T7.4a supplies one.
