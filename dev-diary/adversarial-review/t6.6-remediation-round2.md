## Finding M1, the grant whitelist

Before. The old parser required the literal substring SELECT and rejected the
keywords INSERT and ALL. It never read the privilege list. So
`GRANT SELECT, ALTER ON default.*` passed and the user could run ALTER.

After. `grantPrivileges` captures the text between GRANT and ON. The parser
splits that text on commas and uppercases each entry. It rejects the set unless
every entry equals SELECT. The whitelist rejects every other privilege, known
or unknown. A future ClickHouse privilege cannot slip through.

The parser accepts these strings.

| Grant set | Result |
|---|---|
| `GRANT SELECT ON default.* TO mcp_readonly` | ACCEPT |
| `{"columns": ["GRANTS FOR mcp_readonly FORMAT Native"], "rows": [["GRANT SELECT ON default.* TO mcp_readonly"]]}` | ACCEPT |
| `{"columns": ["GRANTS FOR mcp_readonly FORMAT Native"], "rows": [["GRANT SELECT ON default.* TO mcp_readonly"], ["GRANT SELECT ON default.commits_raw TO mcp_readonly"]]}` | ACCEPT |

The parser rejects these strings.

| Grant set | Result |
|---|---|
| `GRANT SELECT, ALTER ON default.* TO mcp_readonly` | REJECT, names ALTER |
| `GRANT SELECT, ALTER UPDATE ON default.commits_raw TO mcp_readonly` | REJECT, names ALTER UPDATE |
| `GRANT SELECT, DROP TABLE ON default.* TO mcp_readonly` | REJECT, names DROP TABLE |
| `GRANT SELECT, CREATE ON default.* TO mcp_readonly` | REJECT, names CREATE |
| `GRANT SELECT, TRUNCATE ON default.* TO mcp_readonly` | REJECT, names TRUNCATE |
| `GRANT SELECT, INSERT ON default.* TO mcp_readonly` | REJECT, names INSERT |
| `GRANT SELECT, DELETE ON default.* TO mcp_readonly` | REJECT, names DELETE |
| `GRANT SELECT, OPTIMIZE ON default.* TO mcp_readonly` | REJECT, names OPTIMIZE |
| `GRANT ALL ON *.* TO mcp_all` | REJECT, names ALL |
| `GRANT SELECT, FUTUREPRIV ON default.* TO mcp_readonly` | REJECT, names FUTUREPRIV |
| `{"columns": ["GRANTS FOR mcp_readonly FORMAT Native"], "rows": [["GRANT SELECT ON default.* TO mcp_readonly"], ["GRANT INSERT ON default.commits_raw TO mcp_readonly"]]}` | REJECT, names INSERT |
| empty string | REJECT, names no SELECT |

The last envelope is the two-row output the review measured. The parser reads
both rows and rejects the set on the INSERT row.

Old against new. A throwaway program in `/tmp/t66r2pin` ran the old deny list
and the new whitelist over the same strings. The old parser accepted ALTER,
DROP, CREATE, TRUNCATE, DELETE, OPTIMIZE and the unknown privilege. The new
parser rejected all seven.

```text
old=ACCEPT  new=REJECT (names ALTER UPDATE)  ...["GRANT SELECT ON default.* TO mcp_readonly"], ["GRANT ALTER UPDATE ON default.commits_raw TO mcp_readonly"]]
old=ACCEPT  new=REJECT (names ALTER)         GRANT SELECT, ALTER ON default.* TO mcp_readonly
old=ACCEPT  new=REJECT (names DROP TABLE)    GRANT SELECT, DROP TABLE ON default.* TO mcp_readonly
old=ACCEPT  new=REJECT (names CREATE)        GRANT SELECT, CREATE ON default.* TO mcp_readonly
old=ACCEPT  new=REJECT (names TRUNCATE)      GRANT SELECT, TRUNCATE ON default.* TO mcp_readonly
old=ACCEPT  new=REJECT (names DELETE)        GRANT SELECT, DELETE ON default.* TO mcp_readonly
old=ACCEPT  new=REJECT (names OPTIMIZE)      GRANT SELECT, OPTIMIZE ON default.* TO mcp_readonly
old=ACCEPT  new=REJECT (names FUTUREPRIV)    GRANT SELECT, FUTUREPRIV ON default.* TO mcp_readonly
```
