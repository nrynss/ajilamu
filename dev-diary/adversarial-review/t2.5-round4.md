## Job One: The Hunt For The Fifth Way In

The brief told me to assume a fifth path exists until I had genuinely failed to find it. I found
it, and it is finding 1. Here is everything I tried, including what failed.

**The same package lead, which the brief named first.** This is where it broke, and I put it
first because no prior round could have caught it. Rounds 2 and 3 both proved the bypass
unreachable by building an outside package. That proof is correct and I reproduced it. An
outside package fails to compile on `fit.StretchRatio`, `fit.RenderCandidate`, `stretchRatio`,
`renderCandidate`, `applyStretch`, `renderStretch`, `deadBand`, `delta`, `claimOutput` and
`checkRatio`. Ten identifiers, ten `undefined` errors. But the reader who matters is not
outside. `dev-diary/PHASE-2-fit-loop.md` gives T2.6 the path `internal/fit/rewrite.go` and gives
T2.7 the path `internal/fit/loop.go`. Both files will declare `package fit`. I wrote that file
and reproduced the founding defect twice, measured with `ffprobe`.

**How far a compiler enforced fix reaches.** I ran it rather than proposing it. Moving both
functions into `stretch_test.go` keeps the whole suite green and makes my sibling file fail to
build. It closes the two doors that are named, documented and ready to hand. It does not seal
the package. With both functions gone I reached 7085 ms again through `applyStretch`, and again
through `renderStretch`, each in about six lines. So the honest statement is that Go cannot make
this package safe against its own future files, and only a rule the next author reads can. The
artifact carries no such rule today. That absence is the finding.

**What `renderCandidate` costs beyond the band.** It is the worse of the two doors and the
artifact does not say so. It applies no landing check, so a stretch that misses stays on disk.
It calls no `claimOutput`, so it also drops the concurrency guarantee remediation round 3 built.
A sibling that reaches for the candidate renderer loses three protections at once.

**The equivalent mutant, re-judged rather than accepted.** Round 3 and remediation round 3 both
ruled that the landing check reading `StretchDeadBand` instead of `res.Band` is an equivalent
mutant. On the exported surface they are right and I confirmed the reason independently. Across
30,287,527 reachable atempo plans under five budget shapes, every single plan carried a band of
exactly 40 ms. The algebra behind it holds. Atempo needs the miss above the band and at or below
the side budget. The band equals the side budget whenever that product falls under 40 ms, so a
smaller band makes atempo unreachable. The claim is not universal. `prepareRatio` computes the
band with no repair band check. On that path `res.Band` reads 8 ms at a 100 ms slot and 24 ms at
a 300 ms slot, where `StretchDeadBand` reads 40 ms. `stretchRatio` and `renderCandidate` both go
through `prepareRatio`. So the equivalence rests on the same outside the package assumption
finding 1 breaks. The shipped code reads the correct expression, so I raise this as a correction
to the record and not as a separate finding.

**`claimOutput` against hostile output paths.** No escape. I measured five shapes from an
outside package with segment 3 and a 5320 ms slot, which plans atempo. A dangling symlink at the
output returns `ErrOutputExists` and leaves the symlink alone, because `O_EXCL` refuses a
symlink even when its target does not exist. A symlink pointing at an unrelated file returns
`ErrOutputExists` and that file read back byte for byte as `someone else's take`. A directory at
the output returns `ErrOutputExists`. A missing parent directory returns `ErrRenderFailed` with
no file. A read only parent directory returns `ErrRenderFailed` with no file. The design is
right. `checkPaths` reports what was true when it looked and the exclusive create makes the
guarantee.

**Whether `discardOutput` can delete a file it did not create.** No route. It has three call
sites. Two sit in `applyStretch` after `claimOutput` returned nil, and one sits inside
`claimOutput` itself after the create succeeded and the close failed. Every one runs on a path
this call created. A removal that finds nothing treats `os.ErrNotExist` as success, so a
vanished file does not turn into a spurious error.

**Path aliasing.** Refuted. `os.SameFile` catches what string cleaning misses. A relative source
against an absolute output naming one file returns `ErrSameFile`. The mirror returns
`ErrSameFile`. A hard link at the output returns `ErrSameFile`.

**A `Fit` with a zero or negative slot, or a zero measured duration.** All handled. A zero slot
and a negative slot both return `RepairManual` with a zero band and a zero limit. A zero
measured duration against a 5 second slot returns `rewrite`. A negative measured duration
returns `rewrite`. `Stretch` returns `ErrNoSlot` on the first two.

**Duration overflow.** One real hit, and it is finding 4. I probed a slot at the int64 maximum,
a measured duration at the maximum, a 1 nanosecond slot against the maximum, and the minimum in
both fields. Every one routes correctly except the single point where the derived miss lands
exactly on the int64 minimum. Nothing panics anywhere.

**Chained stretch.** Real, documented, and reproduced. Six calls under a 0.10 budget on both
sides walked `seg_8_try1.wav` from 4200 ms to 7101 ms against its real 7110 ms slot. The ratios
ran 0.9000 five times and then 0.9887. Every call returned nil and `ffprobe` measured every
step. The finished artifact reports `Fits` true and replans `none` against the real slot. I
judge the disposition below.

**Concurrency under heavier load than the committed test.** Nothing broke. Thirty trials of four
goroutines each on one output path, under `-race`, gave 30 nil returns and 90 `ErrOutputExists`,
with zero violations. The surviving file matched the winner's slot every time by `ffprobe`.

**The listening harness escaping through its output names.** No escape. The candidate names are
`seg_N_ratio_R.wav` and `seg_N_original.wav`, and no fixture or take carries either shape.

**A crash between the claim and the render.** Real and not a defect. A zero byte file at the
output blocks a later `Stretch` with `ErrOutputExists`, which I measured. The window predates
`claimOutput`, because a killed ffmpeg left a partial file the same way, and the package
correctly refuses to overwrite a take. T2.7 owns take naming and the handoff already says so.
