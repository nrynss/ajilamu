# T2.8 contract change: runner language wiring

## Why this file exists

T2.8a changed the synthesizer language contract. The function now reads:

```go
func NewSynthesizer(cfg *config.Config, language string, rec ChargeRecorder, card cost.RateCard, client TTSClient) (Synthesizer, error)
```

The language binds at construction (`internal/tts/chirp.go:70`). `Synthesize` calls `Assign` with
that stored value (`internal/tts/chirp.go:115`) and sends `LanguageCode` to Cloud TTS
(`internal/tts/chirp.go:128`). The old package pinned `Malayalam`, so a run could not choose its
language.

T2.8b added `Language`, `TargetLanguageName`, and `SourceLanguageName` to `fit.PipelineConfig`
(`internal/fit/loop.go:326-336`). `NewPipeline` rejects an empty or malformed `Language` and an
empty `TargetLanguageName` before any billable call (`internal/fit/loop.go:653-661`). The loop
copies both language names onto every `TranslateRequest` (`internal/fit/loop.go:589-590`).

## The runner wiring landed

T2.8b now wires the runner in `cmd/ajilamu/main.go`. `pipelineRunner` no longer holds a
synthesizer (`cmd/ajilamu/main.go:398`). It holds a `newSynthesizer` factory
(`cmd/ajilamu/main.go:402-404`). `runSynthesizerFactory` builds the factory and calls
`tts.NewSynthesizer(cfg, language, rec, card, client)` (`cmd/ajilamu/main.go:413-417`).
`newPipelineRunner` points the field at it with a nil client
(`cmd/ajilamu/main.go:438`). The segmenter and the translator are still built once.

`pipelineRunner.Run` resolves the language first (`cmd/ajilamu/main.go:447`). A bad code returns
before any client runs. `resolveRunLanguage` (`cmd/ajilamu/main.go:378`) reads a small table
(`cmd/ajilamu/main.go:370`). The table maps the one code the create screen offers onto its
BCP-47 tag and its display name. It holds `ml` to `ml-IN` and `Malayalam`. Any other well formed
code falls back to itself as the display name. An empty or malformed code fails.

`Run` builds the synthesizer with the resolved tag and the run ledger
(`cmd/ajilamu/main.go:459`). It passes `Language: language.tag` and
`TargetLanguageName: language.name` to `fit.RunPipeline` (`cmd/ajilamu/main.go:474-482`). It
leaves `SourceLanguageName` empty. It rebinds the request language to the resolved tag, so the
assembly events name the same code as the pipeline events.

Measured on 2026-09-09 with a throwaway harness in package main. A run started with `ml` built a
synthesizer whose Cloud TTS request carried `Voice.LanguageCode` `ml-IN` and `Voice.Name`
`ml-IN-Chirp3-HD-Achernar`. The pipeline carried `TargetLanguageName` `Malayalam` and an empty
`SourceLanguageName`. An empty code failed with `the run needs a target language`. The code
`not a language` failed with `malformed language code`. The segmenter, the translator, and the
synthesizer factory each saw zero calls. No Cloud TTS request and no charge followed. The
harness was removed after it measured the seam, because a throwaway probe does not belong in
the tree. This task's `owns` line lists `cmd/ajilamu/main_test.go`
(`dev-diary/PHASE-2-fit-loop.md:300`). Three committed tests pin the runner wiring:
`TestPipelineRunnerLanguageWiring`, `TestPipelineRunnerRejectsLanguageBeforeCharge` and
`TestRunSynthesizerFactoryForwardsLanguage`.

## What remains for T7.5b

T7.5b owns `internal/api/run.go` and `cmd/ajilamu/main.go`. It records both languages at upload
and puts both display names on the run request. The runner then sets `SourceLanguageName` from
that request (`cmd/ajilamu/main.go:482`).

`api.RunRequest.Language` still carries the create screen code, such as `ml`
(`internal/api/run.go:57`). The start handler reads it from the `language` query parameter
(`internal/api/run.go:521`) and stores it on the request (`internal/api/run.go:538`). The run
recorder still writes that raw code to the ledger (`cmd/ajilamu/main.go:702`). T7.5b makes the
request carry the full tag.

One defect remains. Take files and resume records carry no language
(`internal/fit/loop.go:182`, `internal/fit/loop.go:827`). The work directory is per dub
(`internal/api/run.go:541`). A second language for one project therefore collides with the first
language's takes. T7.5b owns the run work directory, so it owns that fix.

## What remains for T7.7

T7.7 owns the fetched catalog. It replaces `createScreenLanguages` (`cmd/ajilamu/main.go:370`)
with `internal/tts/catalog.go`. That table is the deletion point. After T7.7 the create screen
sends a code the catalog already names.

## What T7.5b must not do

Do not rebuild the runner per run. Move only the source language. The segmenter and the
translator hold no per-run language state. Do not pass an empty target name. The pipeline fails
the run before any billable call.
