## Findings

| Where | What | Pin | Mutation |
|---|---|---|---|
| `cmd/ajilamu/main.go` lines 1070 to 1081, `editRecorder.RecordEdit` | The adapter reads the dub head and then appends a commit whose parent and version_seq come from that read. The read and the append are not atomic. Two edits in flight read the same head, so both append a child of it at the same version_seq. The history DAG forks. The workspace head is the last commit by version_seq then commit_id, and its ancestry excludes the sibling commits. An edit on a losing branch returns 201 but never reaches the head timeline. The page that confirmed it shows the edit, and a reload loses it. | Twelve concurrent boundary POSTs to one dub all answered 201. `SELECT version_seq, count() FROM commits_raw FINAL WHERE dub_id='t67-race-dub' GROUP BY version_seq ORDER BY version_seq` returned three rows at version 3, three at version 4 and five at version 5. `timeline_at_commit` at the head returned four of the twelve edits. A second dub dropped seven of twelve. | Revert the serialization and concurrent edits fork the history again. Each losing edit reports success and then disappears from the workspace head. |

The fix is a per-dub lock that spans the head read, the commit append, the action and the
snapshot. `runRegistry.start` already serializes one run per dub, so the pattern exists. The
route also reads the head at `internal/api/mutations.go` lines 183 to 194 and derives the
result before the adapter re-reads. The lock must cover the derivation or relative commands can
still compute from a stale head.

## Done condition

**The done condition holds for one edit at a time.** A boundary drag and a command confirmation
each write one commit, one action and one timeline snapshot. The History tab shows both. The
edit survives a reload. The condition fails under concurrent edits, because the head timeline
drops the losing branch. Finding H1 covers that case.

Open notes, not findings:

- The boundary path accepts a slot past the film end. A drag of line 3 to 8250..99999 answered
  201. The route has no film duration to bound against, and the page clamps to
  `pictureDurationMs`, which returns the fixture constant 75008 for every project. The fixture
  stub is pre-existing.
- The adapter flushes after each row, because `EnqueueJSON` flushes. A failure between the
  commit and the action leaves a commit with no action and no snapshot. The route still reports
  failure, so the browser stays behind the ledger. `runRecorder.persist` shares this pattern.
- `mutations_test.go` covers the boundary row, the command row, an invalid command, an
  overlapping boundary, a failed recorder and a project with no timeline. It does not cover an
  empty command, a zero or negative boundary, the adapter, or two edits in flight.
- A no-op boundary writes a commit. The route does not compare the new bounds with the head.
