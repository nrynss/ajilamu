## 1. The source panel DOM

The probe selected line 3, replaced the source field, and opened the source panel. It then
clicked the confirm.

Before the fix, the panel and the confirm read:

```json

  "pendingText": "Re-translating line 3 from the corrected source calls the translation model, then a fresh voice render. Cancel Re-translate line",
  "confirmLabel": "Re-translate line",
  "confirmDisabled": false,
  "sourceHintText": "A corrected source line needs re-translation."

```

After the fix, the same probe reads:

```json
{
  "pendingText": "Re-translating line 3 from the corrected source needs a route that runs the translation model first. The landed re-render route accepts a corrected target line only, so no handler takes a corrected source line yet. T6.5b owns that path.   "confirmLabel": "Re-translate line",
  "confirmDisabled": false,
  "sourceHintText": "A corrected source line needs re-translation. T6.5b lands that path."
}
```

The confirm button state is `enabled` before and after. The panel now reports the missing
route before the creator confirms, which is the first clause of M1. The confirm no longer
promises a call, because the panel above it says the confirm sends nothing.
