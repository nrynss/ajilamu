# T6.5 ghost take history: round 1

**Verdict: REMEDIATE.** Counts: **C 0, H 1, M 2, L 0.**

The page renders ghost and active take chips and shows the fee before each re-render. One
defect blocks the done condition. On a real project no take plays, because the wire carries an
absolute server path and no route serves it. The bundled fixture hides that, because its take
files are build assets. The ghost history also sits in a page strip above the timeline, so the
timeline lanes carry no ghost shape. I fix nothing.

## What I measured

I copied the tree to `/tmp/t65/repo`, symlinked `node_modules`, and ran `npm run build`. A
throwaway Node server served the built bundle. It returned the frozen `testdata/wire/dub.json`
under the non-fixture id `t65-real-dub`, and a ledger-shaped copy under `t65-ledger`. I drove
the page with headless Chromium through Puppeteer, with the cache disabled. The working tree
was never edited.

### 1. The chips

Line 3 selected. The ghost chip carried `data-take-file` `seg_3_try1.wav` and `data-take-state`
`ghost`. Its computed style was `border-style: dashed`, `background-color: rgba(0, 0, 0, 0)`,
and `opacity: 0.72`. The active chip carried `data-take-file` `seg_3_stretched.wav` and
`data-take-state` `active`. Its computed style was `border-style: solid` and
`background-color: rgb(143, 165, 140)`. Both are native `BUTTON` elements.

### 2. Playback

A ghost click fetched `/_app/immutable/assets/seg_3_try1.xBIiyNfY.wav` with status 200 and
type `audio/wav`. An active click fetched
`/_app/immutable/assets/seg_3_stretched.ClDJvJby.wav` with status 200 and type `audio/wav`.
Each click fetched exactly one take. Those hashes match the handoff.

The fixture case is the only case that plays. On the `t65-ledger` payload both chips and the
line 3 `Play take` button showed the missing-URL note and fetched nothing.

speaker re-render line 3 held three chips. They read ghost, ghost, active, with `Try 1`,
`Try 2` and `Try 3`. The new active chip was the absolute-path take, so a click showed the
missing-URL note.

## Review angles

1. The ghost history is not on the timeline. The strip sits above the `Timeline` component,
   and `Track.svelte` renders only the active take. Finding M above.
2. The fixture hides the defect. On a real project the wire `file` is an absolute server path
   and no route serves it, so neither take plays. Finding H above.
3. Every re-render path shows an estimate before the call. The run button does not, and it
   predates this patch.
4. Keyboard access works. A three-take line renders ghost, ghost, active.

## Handoff check

The handoff matches my measurements. The chip attributes and the two computed styles
reproduce. The two fetched asset hashes, the fee, the POST body and the 201 take reproduce.
The three chip states, the missing-URL note, the fixture request count and the `npm check`
line reproduce.
The `re-roll path stays unwired` sentence holds, because no control sends an empty body. The
`isolated world` sentence does not describe Puppeteer's default `page.evaluate`, but network
capture confirms its conclusion.

## Residue

The run button starts a billable run and shows no estimate before the call. That gap predates
this patch and belongs to the run task, so I file nothing.

The `aria-pressed` attribute on a chip labels a play button as a toggle. It is minor and I do
not file it.

The aborted `/clip.mp4` requests in my harness are a stand-in artifact, because my server does
not carry the video. The page raised no error.

## Done condition

The done condition does not hold. The timeline shows the ghost history only in the editor
strip, not in the timeline lanes. Both fixture takes play, but no real take plays. The
estimate does show before every re-render call.
