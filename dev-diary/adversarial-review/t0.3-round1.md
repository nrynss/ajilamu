## Verification

We verified the implementation through six independent checks.

First, we measured audio take durations using ffprobe directly. The measurements confirm the exact millisecond values that the specification requires.

```
$ ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 scratch/takes/seg_3_try1.wav
5.720375
$ ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 scratch/takes/seg_3_stretched.wav
5.337563
```

Raw values round to 5720 ms and 5338 ms respectively.

Second, we verified audio stream properties of the source video clip using ffprobe directly.

```
$ ffprobe -v error -select_streams a:0 -show_entries stream=codec_name,sample_rate,channels,channel_layout,bit_rate -of json assets/source/clip.mp4
{
    "streams": [
        {
            "codec_name": "aac",
            "sample_rate": "44100",
            "channels": 2,
            "channel_layout": "stereo",
            "bit_rate": "132532"
        }
    ]
}
```

Third, we tested ffmpeg audio demuxing independently. The demuxed stream matches the required 16 kHz mono PCM format.

```
$ ffmpeg -y -i assets/source/clip.mp4 -vn -ac 1 -ar 16000 -c:a pcm_s16le /tmp/test_demux.wav
$ ffprobe -v error -select_streams a:0 -show_entries stream=codec_name,sample_rate,channels -of json /tmp/test_demux.wav
{
    "streams": [
        {
            "codec_name": "pcm_s16le",
            "sample_rate": "16000",
            "channels": 1
        }
    ]
}
```

Fourth, we verified time stretching on a short take. Applying a ratio of 0.8 slows down the audio and increases duration from 4.200 seconds to 5.237 seconds.

```
$ ffmpeg -y -i scratch/takes/seg_8_try1.wav -filter:a "atempo=0.8" /tmp/test_seg8_slow.wav
$ ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 /tmp/test_seg8_slow.wav
5.236938
```
