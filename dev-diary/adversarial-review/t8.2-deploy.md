## TLS hostnames and certificates

Caddy serves one site block for both names and obtains one certificate per name over the HTTP-01 challenge.

| Hostname | Public DNS | Certificate issuer | Subject | Valid from | Valid to |
|---|---|---|---|---|---|
| `ajilamu.nryn.dev` | `34.63.219.30` | `C=US, O=Let's Encrypt, CN=YE1` | `CN=ajilamu.nryn.dev` | Sep 9 14:50:52 2026 GMT | Dec 8 14:50:51 2026 GMT |
| `34-63-219-30.sslip.io` | `34.63.219.30` | `C=US, O=Let's Encrypt, CN=YE2` | `CN=34-63-219-30.sslip.io` | Sep 9 14:41:28 2026 GMT | Dec 8 14:41:27 2026 GMT |

`ajilamu.nryn.dev` is the custom name. Its A record is DNS-only (grey cloud), so the ACME HTTP-01 challenge reaches this origin directly rather than through a proxy. The sslip.io name encodes the reserved address and stays the fallback.

`verify.sh` pins the origin address with `curl --resolve` and `openssl s_client -connect`, so the measurement never depends on the operator resolver cache. The operator machine resolved `ajilamu.nryn.dev` minutes after the authoritative nameservers did, and that local lag first made a clean deploy look failed.

## Findings

**H. The named Text to Speech role does not exist.** The task and `infrastructure.md` named `roles/cloudtexttospeech.user`. `gcloud iam roles describe roles/cloudtexttospeech.user` returns `not found`. So does `roles/cloudtts.user` over both the CLI and the REST API. A FULL scan of 2,389 predefined roles found no role carrying any `texttospeech.*` permission. A Chirp synthesize call from the host with `roles/aiplatform.user` alone returned HTTP 200. The synchronous API checks no texttospeech permission. `deploy/provision.sh` now grants the measured role list and stops with an error when the project rejects a role. `infrastructure.md` carries the correction.

**H. The mcp unit could not reach ClickHouse Cloud.** `systemd/ajilamu-mcp.service` loaded only the secret file, so the compose file interpolated an empty `CLICKHOUSE_HOST` and the container dialled `localhost:8443`. The container health check reported `starting`, and the log carried `Connection refused` against `https://localhost:8443`. The unit now carries the non-secret connection settings. The pin is `mcp health healthy` plus `tools/call list_databases` returning `["ajilamu"]`.

**M. `run-sample.sh` measured no audio level.** `ffmpeg -v error` suppressed the `volumedetect` line, which reports at info level, and `pipefail` then aborted the script on the empty `grep`. The export was already correct. The script now drops `-v error` and guards the `grep`. The corrected command measures the tail in run 2 and run 3.

**M. `verify.sh` measured TLS before issuance finished.** A clean rebuild raised `tlsv1 alert internal error`, because Caddy issues certificates after it starts. The script now polls `healthz` until HTTP 200. The first clean rebuild failed on this and the second passed.

**M. `roles/storage.objectAdmin` does not carry `storage.buckets.get`.** The bucket metadata read returns HTTP 403. The role does carry `storage.objects.list`, which returns HTTP 200. `verify.sh` lists objects rather than reading the bucket, because that is the permission the host actually holds.

**M. The host ffmpeg differs from the frozen stack.** `AGENTS.md` freezes ffmpeg n9.0.1. The Ubuntu 24.04 package installs 6.1.1-3ubuntu5. Every run in this record used the host build and passed. I did not pin a static n9.0.1 build, because the distro package keeps the deploy reproducible from `deploy/` alone. The drift is real and it stays on the record.

**Observation. The Go server binds `*:8080`.** `cmd/ajilamu/main.go` listens on `":" + port`, so the listener is reachable from VPC peers through `default-allow-internal`. No firewall rule allows 8080 from outside the network. A T8.2 change cannot narrow the bind address without editing Go, which is outside my paths.

**Observation. The first ClickHouse `CREATE USER` timed out.** The statement returned no bytes after 120 seconds. An identical retry completed in 0.62 seconds, and the user appeared. The script has no retry, so a rerun is the operator path. This looks like transient Cloud DDL behaviour rather than a defect I can fix in the script.

**Observation. One live run failed inside the pipeline, not the deploy.** Run 1 ended in an error after 204 seconds with 54,152,550 nanodollars spent and no export. The server log names the cause:

```
ERROR run failed run_id=a6c3f543b1495225f3f1299d2516411f dub_id=0d029e6fc85ae5f1057b46ac2a291171 stage=repairing
error="repair line 7: synthesize line 7 attempt 2: rpc error: code = InvalidArgument desc =
This request contains sentences that are too long. ... Sentence starting with: \"ഭൗതിക\" is too long."
```

Cloud Text to Speech rejected one long Malayalam sentence that the rewrite produced. Runs 2 and 3 on the same host finished. This is a Phase 3 pipeline defect, and it is not a deploy finding.

## Credentials

No credential appears in the repository, the bundle, an image layer, or this record. `deploy/build.sh` stages no `.env`. The bundle lists no `.env` member. The `mcp-clickhouse` image installs from PyPI and receives every secret at runtime. The five secrets reach the server through `/run/ajilamu/env` at mode 0600 on tmpfs, and `GOOGLE_APPLICATION_CREDENTIALS` is absent from the server environment. The ClickHouse writer credential travels in a curl config file at mode 0600 and never in argv. The probe accounts created during development were dropped, and `system.users` now holds `mcp_readonly` alone.
