## Run request pin

`RunRequest{dub= dub-languages, language="ml-IN", source_language="en-US", workdir=.../dub-languages/work/ml-IN}`.
For a record with no source language the request carried `language="ml"` and

language therefore reaches `RunRequest.SourceLanguage` and then
`fit.PipelineConfig.SourceLanguageName` through `resolveLanguageName`. The value is the code,
which is H1.

## Prompt pin

`resolveLanguageName("en-US")` returned `en-US`. `resolveRunLanguage("ml-IN")` returned
`{tag: "ml-IN", name: "ml-IN"}`. The composed prompt read:

```text
Translate this en-US dialogue line into natural spoken ml-IN:
Original en-US: "Hello from orbit"
Speaker emotion: Warm
Constraint: The translated line will be spoken in ml-IN in a video slot that lasts approximately 1.8 seconds (1820 ms). Keep the translation natural, spoken, and fit the rhythm.
```

The named pair produced `Translate this English dialogue line into natural spoken Malayalam
script (മലയാളം):` and `Respond with strictly the translated Malayalam text.` The code pair
lost the script hint and named the code three times.

## Handoff claims

The handoff claims hold where they can be measured. The browser submit stored `en-US` to
`ml-IN` and answered 201. The sample wrote `en` to `ml`. The route served the stored source
language through the handler with a stand-in reader. The older record kept its title and
served an empty source language. The tests passed and the web check reported 0 errors.

One claim understates the defect. The handoff records the probe
`TranslateRequest{TargetLanguageName:"Malayalam", SourceLanguageName:"en"}`. That is the
sample path. A new upload sends `ml-IN` and `en-US`, so the named pin does not cover the path
the create screen now uses. The Surprises paragraph admits the code fallback but treats it as
acceptable. H1 treats it as a defect against the user requirement.

## What I did not file

- **The empty source default.** The source picker starts empty and the form submits an empty
  value. The spec asks for that behaviour, because the film language may be unknown. The
  stored record then carries `"source_language":""`. I measured it and filed nothing.
- **The sample spelling.** The task text fixes `en` to `ml`. The form now uses catalog codes.
  H1 covers the prompt consequence. The spelling is deliberate.
- **The frontend ignores `source_language`.** `web/src/lib/types.ts` declares the field and no
  component reads it. The done condition is about the payload, not the screen.
- **A fresh project cannot start a run from the workspace.** The payload derives `languages`
  from the ledger and a new project has no tracks. T7.5 shipped that behaviour. T7.5b did not
  change it.
