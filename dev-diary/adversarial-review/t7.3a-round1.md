## Findings

| # | Sev | Where | What | Pin | Mutation |
|---|---|---|---|---|---|
| 1 | M | `internal/fit/loop.go:232-237` | `readSegmentRecord` accepts any recorded take that exists. A zero-length take passes the `os.Stat` check. `reusableTake` then returns it, so `repairSegment` hands it to `RepairLine` through `InitialTake`. `RepairLine` calls `media.Duration` on the empty file, which fails, so the whole resumed run aborts. A flagged or stretched record takes the replay branch instead, so the run silently adopts the empty file as the chosen take. An empty take is not completed work, so the loop must re-render the line. | `TestPinEmptyTakeFallsBack` failed on the working tree with `repair line 1: source take could not be probed: ... Invalid data found when processing input`, and the synth was never called. `TestReviewFlaggedEmptyTake` returned a nil error with the empty file as the chosen take. | Adding a zero-length check to `readSegmentRecord` made `TestPinEmptyTakeFallsBack` render with an overwriting synth. Ignoring the missing-file check survives the shipped tests, which shows the shipped tests never exercise take validity. |

The fix is to treat a take that is empty or unmeasurable as no record, and to clear that file
before the fresh render claims the same path.

## What I did not file

- **A line interrupted mid-attempt cannot resume.** `TestPinStaleTakeMustNotBlockResume` failed
  on the working tree with `repair line 2: synthesize line 2 attempt 1: tts refuses to overwrite
  .../seg_2_try1.wav`. A line that needs a rewrite writes `seg_2_try1.wav` on attempt one, then
  the run dies on attempt two and writes no record. On resume the loop re-renders attempt one to
  the same path, and the production synthesizer refuses to overwrite. The Done-when test stops
  after a completed take, so I judged this mid-attempt interruption outside the stated acceptance.
  The collision is the pre-existing overwrite refusal the completed-take detection exists to work
  around.
- **The resumed run's cumulative cost starts at zero.** The replayed line adds no charge, so the
  resumed run reports 0 for it and its events carry only the resumed run's total. The ledger holds
  the first run's charges, so the project counts each segment once. I treat the reset as a
  consequence of a new run, and the task asks for a decision here.
- **The record name does not carry the language.** Two languages in one work directory would
  overwrite each other's records. Take names collide across languages anyway, so one language per
  work directory is already the contract.
- **The record requires an exact segment match.** A re-segmented line rejects the record and
  renders again. I could not measure the production segmenter's determinism, so I did not file it.
- **The no-record path leaves a new file.** Every rendered line now writes
  `seg_<id>_result.json` into the work directory. Nothing enumerates that directory, so behaviour
  is otherwise unchanged.
