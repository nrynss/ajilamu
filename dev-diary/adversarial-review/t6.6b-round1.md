## Observations that are not findings

These are recorded so the next round does not rediscover them. None is a defect today.

The offer hardcodes 150 and 600 in the template. They match `cost.DefaultRateCard` and no
environment variable overrides that card, so the numbers are true. No route exposes a rate card
to the frontend, so the task had no shared source to read. A future rate change would make the
sentence lie, and no test binds the two. The H1 fix touches this sentence anyway, so the
remediator should consider naming the coupling in a comment.

`revise()` clears the intent and leaves the agent answer and its charge on screen. A later
`submit()` clears both, and `confirm()` clears the answer. The displayed charge stays a true
measurement of a turn that really ran, so nothing on screen becomes false.

The response carries one charge per model call and the page shows only the total. T6.6a measured
two model calls in one turn. The `ui-ux.md` requirement to say what a total covers addresses the
running cost meter rather than a single turn, so this review does not read it as a defect here.

Svelte escapes `{agentTurn.answer}`, so an answer carrying markup renders as text.
