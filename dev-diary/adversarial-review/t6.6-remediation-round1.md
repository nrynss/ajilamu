## Grant strings

The parser accepts these strings.

| Grant set | Source |
|---|---|
| `GRANT SELECT ON default.* TO mcp_readonly` | Measured. `SHOW GRANTS FOR mcp_readonly` on the pin container. |
| `{"columns": ["GRANTS FOR mcp_readonly FORMAT Native"], "rows": [["GRANT SELECT ON default.* TO mcp_readonly"]]}` | Measured. The `run_query` tool envelope for the same query. |

The parser rejects these strings.

| Grant set | Source |
|---|---|
| `GRANT SELECT, INSERT ON default.* TO mcp_writer` | Measured. `SHOW GRANTS FOR mcp_writer` after a SELECT and INSERT grant. |
| `GRANT ALL ON *.* TO mcp_all` | Synthetic. The literal token ALL. |
| `GRANT INSERT ON default.* TO mcp_writer` | Synthetic. No SELECT and a write privilege. |
| empty string | Synthetic. No grant names SELECT. |

Measured ClickHouse facts on 25.3.14.14. `GRANT ALL ON default.*` expands into the full
privilege list. That list carries INSERT, so the keyword check catches it. The literal token
ALL does not appear in the expanded output. The literal check stays for other versions.

## Required probe fix

The probe could not read the grant text without a second fix. ADK returns the MCP structured
content when the server sets it. `mcp-clickhouse` nests its text under `result`. The old
`callTool` asserted a string on `out["output"]` and read an empty value. The new `toolText`
unwraps the structured content and keeps the text fallback. This fix is inside H1, because
the grant assertion cannot run without it.
