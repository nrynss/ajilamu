# T6.5b source-text re-translation path: round 1

**Verdict: REMEDIATE.** Counts: **C 0, H 1, M 0, L 0.**

The source path works. A corrected source line replaces the stored transcript, runs the
translation model once, writes a new take beside the old ones, and records the take, its
charges, one commit, one `text_corrected` action, and one timeline snapshot. The page
sends `source_text` and applies the answer. The target path keeps translation at zero only
when attempt one fits. A corrected target line that misses its slot makes the fit loop
translate the source on attempts two and three. That bills translation and can replace the
creator's text. The done condition does not hold for that case.

## Findings

| Where | What | Pin | Mutation |
|---|---|---|---|
| `cmd/ajilamu/main.go:636-645` | **H.** A corrected target line is authoritative. T6.5b's done condition requires zero translation calls on the target path. `RenderLine` passes `InitialText` and `MaxAttempts: fit.DefaultMaxAttempts`. `fit.RepairLine` reads `InitialText` on attempt one alone, then translates the source on attempts two and three with `ModeShorter` or `ModeFuller`. A corrected target that misses its slot therefore calls the translation model. The chosen take can speak the model's rewrite instead of the creator's text. The page applies that rewrite to the target line. The new test at `internal/api/rerender_test.go:672-692` covers only a slot-fitting take, so it does not pin the done condition. The handoff records the gap as a surprise. | Real fit loop through the route seam on segment 3's 5320 ms slot. A 10 second attempt one recorded translation calls = 2 and synthesis calls = 3. With a rewrite that fits, translation calls = 1, chosen attempt = 2, and the take spoke `translated source line` while the creator sent `corrected target line`. | A revert leaves the target path billing translation and overwriting the creator's authoritative text. |

The concrete fix keeps one attempt for an authoritative text, so the loop never
translates the source to second-guess the creator:

```go
	maxAttempts := fit.DefaultMaxAttempts
	if req.Text != "" {
		// A corrected target line is authoritative. The loop must not
		// translate the source to second-guess the creator.
		maxAttempts = 1
	}
	line, err := fit.RepairLine(ctx, req.Segment, fit.RewriteConfig{
		Translator: &namedTranslator{
			inner:  p.translator,
			target: language.name,
			source: resolveLanguageName(req.SourceLanguage),
		},
		Synthesizer: synthesizer,
		WorkDir:     req.WorkDir,
		PathBuilder: rerenderTakePath(req.TakeFile),
		MaxAttempts: maxAttempts,
		InitialText: req.Text,
	})
```

### 2. The target path

`TestRerenderCorrectedTargetSkipsTranslation` recorded `translation calls = 0, synthesis
calls = 1`. That holds while attempt one fits.

A corrected target that misses its slot behaves differently. I drove the real fit loop
with a synthesizer that returns a 10 second WAV for the creator's text.

```text

```

With a synthesizer that returns the slot length for the model's rewrite, the loop chose
attempt two and the take spoke the rewrite.

```text

```

The route's 201 then carries the rewrite in `text`. The page applies that value to the
target line. The panel promised `no translation model runs` before the call.

## Handoff check

The handoff entry matches every measured claim. The route takes `source_text`. The 201
carries `text` and `source_text`. The action reads `text_corrected` with `manual_ui`. The
page sends `source_text` and applies the answer to the source segment and the active track
line. The counts read one translation call on a fitting source take and zero on a fitting
target take. Both commands reproduce.

Two gaps in the handoff evidence. The captured row shows the action alone. The task also
requires one timeline snapshot. I measured that snapshot and it lands, so the code is right.
The handoff should have named it. The handoff's surprise paragraph records the two
translation charges on a target miss. The done condition forbids them, so the task is not
done.

## Done condition

The done condition reads: a corrected source line re-translates and re-renders as a new
take, the translation model runs on that path and zero times on the target-text path, and
the page applies the response.

The source half holds. One translation call, a new take beside the old ones, and the full
ledger record. The page half holds for both paths. The target half holds only when attempt
one fits. A corrected target that misses its slot calls the translation model and can
overwrite the creator's text. The done condition therefore does not hold. Verdict
REMEDIATE.
