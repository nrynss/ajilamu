Verdict: REMEDIATE

Counts: C 0, H 0, M 1, L 0.

## Scope and evidence

I reviewed the T4.2a diff against its task contract, T4.6's approved ownership change,
the frozen `takes_raw.peaks Array(UInt8)` schema, and the approved T4.2 recorder contract.

The recorder adds `Peaks []uint8`, names `peaks` in the actual `takes_raw` JSONEachRow
query, and rejects nonempty vectors outside 64 through 128 samples before `EnqueueJSON`.
`takePeaks.MarshalJSON` converts every byte to an integer, so the transport representation
is a JSON number array rather than Go's base64 encoding for `[]uint8`.

I inspected the local HTTP capture boundary in `TestRecordTakeFixtureCapture` and ran it
fresh. Its handler parses the POST body as JSONEachRow. The captured 64-sample vector equals
the input values, and the empty vector is an empty JSON array. T4.2's ten take rows, thirty
itemized charge rows, segment 8 delta of `-2910`, retry identity, and invalid-delta
pre-transport rejection remain present.

`go test ./internal/ledger -count=1 -run '^TestRecordTakeFixtureCapture$' -v`,
`go test ./internal/ledger -count=1`, `go test ./... -count=1`, `go vet ./...`,
`gofmt -d internal/ledger/takes.go internal/ledger/takes_test.go`, and `git diff --check`
on the T4.2a Go paths passed.
