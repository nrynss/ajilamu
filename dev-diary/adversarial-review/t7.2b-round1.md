## What I did not file

- A post-connect failure reports waking. `ClickHouseSecure=true` against a plain HTTP listener
  returned 503 waking in 0.8ms. A wrong scheme or a listener that resets reports waking forever.
  The fixed contract has no row for a post-connect failure other than a timeout, so I read this
  as a contract gap rather than an implementation defect. I record the measurement here for the
  orchestrator.
- The keep-alives flag is redundant. Each probe builds its own transport, so enabling keep-alives
  changed nothing in my run. It is harmless and it documents intent, so I did not file it.
- The two test packages duplicate four helpers. `closedPort` mirrors `reserveClosedPort`,
  `standInConfig` mirrors `clickHouseFixtureConfig`, `readyServerURL` mirrors
  `newLedgerReadyServer`, and `ledgerReadyStatus` mirrors `ledgerReadyRequest` plus
  `ledgerReadyPayload`. The package split forces the duplication, so I did not file it.
- The T7.2b block still reads `status: claimed:orchestrator`, and the handoff log carries no
  T7.2b entry. Both belong to the task owner and the orchestrator rather than to this review.
- Three prior review records still quote the retired `ClickHouse did not answer a ping.` text.
  They are history rather than live docs, so I did not file doc drift.
- `internal/api/server_test.go` still imports `internal/ledger` at line 27. That import is the
  reason the seam exists, and the handoff record names it, so it is correct as it stands.
