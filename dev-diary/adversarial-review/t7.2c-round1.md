### Contract rows, measured end to end

I built `/tmp/t72c/ajilamu` from the working tree. I ran it with `CLICKHOUSE_HOST` pointed at my
own Python stand-in at `/tmp/t72c/ch_standin.py`. The stand-in serves the three ledger statements

| Request | Status | Body |
|---|---|---|
| `GET /api/dubs/{fixture}/history` | 200 | 3 commits from my stand-in, `version_number` 1, 2, 3 |
| `GET /api/dubs/{fixture}/timeline?language=ml&commit=commit-a` | 200 | `commit_id`, `language`, 2 segments |
| `GET /api/dubs/{fixture}/branches?language=ml&a=commit-a&b=commit-b` | 200 | `a` slot 2400ms, 2 takes, `attributed_cost_usd` 1.23, `b` slot 1100ms, 1 take, 0.75 |

| a real read error | 500 | `{"error":"Could not read the ledger history."}` |

Every one of those responses carried the JSON content type with `charset=utf-8` and
`Cache-Control: no-store`.

The 400 rows made zero ledger calls. I counted the stand-in log lines before and after five
rejected requests. The count stayed at 9.

The 500 row hid the internal text and logged it. The hub broker injects the workstation cloud
credentials, so one process reached the real ClickHouse endpoint and timed out. The response was
`{"error":"Could not read the ledger history."}`. The log carried the full request URL and
`context deadline exceeded (Client.Timeout exceeded while awaiting headers)`.

## What I did not file

- The workspace page throws `effect_update_depth_exceeded` on load. The page effect at
  `web/src/routes/d/[id]/+page.svelte` reads `dub` after it writes `dub`, so Svelte aborts the
  effect. The error then stops rail tab switching, so the History tab never mounts in the real
  app. I measured the same error at HEAD `26ce432`, whose web sources do not carry this patch. I
  also measured that clicking the Details tab at HEAD fails the same way. The defect is
  pre-existing and out of scope for this diff. It does block the task's done-when in the running
  app, so the orchestrator may want a separate task.
- A nil reader beats a missing query parameter. `GET .../timeline` with no parameters answers 503,
  not 400. The contract states both rows and states no precedence. I did not file this because a
  fix needs an unstated assumption about which row wins.
- The typed nil adapter mutation survives the shipped suite. No shipped test pins the `main.go`
  wiring. The process pin caught it, because the credential-cleared process answered 500 instead
  of 503. The patch itself assigns the adapter inside the branch, so the shipped code is correct.
- The three new TypeScript interfaces `TimelineView`, `BranchComparison`, and `BranchSummary` have
  no consumer. The contract defines the routes and the types document the wire. No code path
  changes, so I did not file it.
- The 500 pin needed a real read error. I used the workstation cloud credentials that the hub
  broker injects. That measured a genuine timeout against the real endpoint.
