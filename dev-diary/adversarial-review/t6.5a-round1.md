# T6.5a line re-render route: round 1

**Verdict: REMEDIATE.** Counts: **C 1, H 0, M 0, L 1.**

The route works on a project whose ledger track is a catalog tag. It fails on the bundled
fixture and sample, whose track is `ml`. It also carries one handoff pin that nobody can
re-run. The done condition does not hold for the demo project.

### Finding 1 detail

The ledger view filters on exact equality (`sql/schema.sql:909`,
`AND language = {language:String}`). The write side never normalizes. The evidence that the
fixture track is `ml` is in three places.

- `testdata/wire/dub.json` carries one language track, `ml`. `web/src/lib/fixture.ts` reads
  that file, and `web/src/routes/d/[id]/+page.svelte:90` seeds `activeLanguage` from it.
- `testdata/manifest.json` names `ml` for the same project.
- `internal/api/workspace_test.go:167` builds the workspace stand-in with `languages:
  []string{"ml"}`.

`runWorkDirFor` maps `ml` onto `work/ml-IN`. That mapping is correct for the take directory.
The finding is only about the ledger read key.

Concrete fix, reading the caller's code first and falling back to the tag:

```go
		entry, err := headLine(r.Context(), history, dubID, language, segmentID)
		if err != nil {
			logHistoryFailure(logger, "read the head line", err)
			writeHistoryFailure(w, http.StatusInternalServerError, rerenderReadFailed)
			return
		}
		if entry == nil && tag != language {
			entry, err = headLine(r.Context(), history, dubID, tag, segmentID)
			if err != nil {
				logHistoryFailure(logger, "read the head line", err)
				writeHistoryFailure(w, http.StatusInternalServerError, rerenderReadFailed)
				return
			}
		}
```

## Done condition

The done condition holds for a project whose ledger track is a catalog tag, such as an upload
recorded as `ml-IN`. It does not hold for the bundled fixture or sample, whose track is `ml`.
The route answers 404 before it renders, so it writes no take, charges nothing, and records
nothing. T6.3 and T6.5 both call this route on the demo project.
