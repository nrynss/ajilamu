### The residue is closable offline

The remediation says no offline test reaches `newPipelineRunner`. I measured that claim.
`newPipelineRunner` with a full config calls `genai.NewClient`, which calls
`credentials.DetectDefault`. Without ADC that call fails with `failed to find default
credentials`. With a fabricated service account file in `GOOGLE_APPLICATION_CREDENTIALS` the call
succeeds offline. So a test can reach the production closure.

A cleaner fix needs no fabricated credentials. I extracted the closure into a factory that takes
a `tts.TTSClient`. I called that factory with a fake client. The clean tree passes. The same
hardcoded mutation fails.

```
$ go test -count=1 -run 'TestProbeSeamFactoryForwardsLanguage' -v ./cmd/ajilamu

$ sed -i 's|return tts.NewSynthesizer(cfg, language, rec, card, client)|return tts.NewSynthesizer(cfg, "ml-IN", rec, card, client)|' cmd/ajilamu/main.go
```

The seam costs about eight production lines and one test. It uses no ADC and no network. The
codebase already injects clients into `tts.NewSynthesizer` and `gemini.NewSegmenter`, so the
pattern fits.

### M1: The production synthesizer factory has no pin

The runner builds its synthesizer through the closure at `cmd/ajilamu/main.go:429-431`.
`TestPipelineRunnerLanguageWiring` substitutes that field at `cmd/ajilamu/main_test.go:703`, so
it never runs the production closure.
`TestNewPipelineRunnerReturnsNilWithoutDependencies` passes a nil config and an empty config, so
it returns before the closure exists. No committed test observes the language this closure
forwards.

The residue survives. A closure that hardcodes `ml-IN` passes all five named packages. An
`es-ES` run then carries `es-ES` into the prompt and `ml-IN` into the voice. The API already
accepts any code through the `language` query at `internal/api/run.go:521`, so the bad path is
reachable today. Round 1 M2 named this exact mutation.

The remediation disclosed the gap and judged it unreachable. The judgment is wrong. The path
needs credentials, not a network. A fabricated service account file or an injected client both
reach the closure offline. The injected client fits the codebase and needs no fake credentials.

Fix cost: extract the inline closure into a factory that accepts a `tts.TTSClient`. Point the
`newSynthesizer` field at `runSynthesizerFactory(cfg, card, nil)`. Add one test that calls the
factory with a fake client and asserts the Cloud TTS `LanguageCode`. I measured that fix. It
passes clean and fails the hardcoded mutation.

```go
// runSynthesizerFactory builds the per-run synthesizer factory. Production
// passes a nil client, so Cloud TTS opens on ADC. A test passes a fake client.
func runSynthesizerFactory(cfg *config.Config, card cost.RateCard, client tts.TTSClient) func(language string, rec tts.ChargeRecorder) (tts.Synthesizer, error) {
	return func(language string, rec tts.ChargeRecorder) (tts.Synthesizer, error) {
		return tts.NewSynthesizer(cfg, language, rec, card, client)
	}
}
```
