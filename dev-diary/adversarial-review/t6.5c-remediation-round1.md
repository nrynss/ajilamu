# T6.5c serve take audio: remediation round 1

I fixed the one finding from `t6.5c-round1.md`. I did not change the verdict.

| Finding | Fix | Pin | Residue |
|---|---|---|---|
| **M.** `pathInside` compared the joined path with the storage root and never resolved a symlink, so `os.Open` served an outside file through a link inside the root. | `TakeAudioHandler` resolves the root-relative path and opens it with `os.OpenInRoot(root, relative)`, which refuses an escape through a symlink. The handler comment now states that behaviour. | `TestTakeAudioRefusesSymlinkEscape` places a link inside the work directory that points to a file in another directory, then requires 404 with no outside bytes. Reverting the open to `os.Open` answers 200 with the 8044 byte outside file. | None. The lexical guard still runs before the open. |
