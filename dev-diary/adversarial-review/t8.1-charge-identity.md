## Pre-fix reproduction

The pre-fix tree came from `git archive HEAD`, so it carries no working tree change.
The harness ran against database `ajilamu_t81_pre`.

```text
run reported total = 1097700 nanodollars over 6 charges
ledger total = 1076700 nanodollars
covers = "0 segment calls, 1 translation call, 1 render call, and 0 agent calls."
gap = 21000 nanodollars
```

The line rendered three attempts. Attempt 1 and attempt 2 each billed 35 candidate tokens at 0.0000006 USD. The writer stamped both rows with the chosen attempt 1, so the two rows hashed alike.

```sql
SELECT count() AS rows, uniqExact(event_key) AS keys
FROM charges
WHERE dub_id='t81-dub' AND kind='translate' AND unit='candidate_tokens' AND units=35;
-- 1  1
```

The charges view held 8 rows and 8 distinct `event_key`s summing to 1,076,700 nanodollars. The two identical candidate calls contributed one row of 21,000 nanodollars instead of two.

## Post-fix measurement

The same harness ran against database `ajilamu_t81_fix`.

```text
run reported total = 1097700 nanodollars over 6 charges
ledger total = 1097700 nanodollars
covers = "0 segment calls, 3 translation calls, 3 render calls, and 0 agent calls."
gap = 0 nanodollars
```

The two identical candidate calls now store two rows with distinct attempts and distinct keys.

```sql
SELECT count() AS rows, uniqExact(event_key) AS keys
FROM charges
WHERE dub_id='t81-dub' AND kind='translate' AND unit='candidate_tokens' AND units=35;
-- 2  2

SELECT kind, count() AS rows, uniqExact(event_key) AS keys,
       sum(toInt64(round(cost_usd * 1000000000))) AS nanos
FROM charges WHERE dub_id='t81-dub' GROUP BY kind ORDER BY kind;
-- translate   6  6   107700
-- synthesize  3  3   990000

SELECT count() AS rows, uniqExact(event_key) AS keys,
       sum(toInt64(round(cost_usd * 1000000000))) AS nanos
FROM charges WHERE dub_id='t81-dub';
-- 9  9  1097700
```

The candidate rows themselves, with attempt and key:


On the deployed run the same row would raise the view to 50 rows and 56,905,350 nanodollars, which is the run-reported figure. The covers sentence would read 16 translation calls and 16 render calls.

## Resend check

The fix must not defeat retry dedup. One take written twice through `RecordTake` left 6 rows in `charges_raw` and 3 rows in the view.

```sql
SELECT count() AS rows FROM charges_raw WHERE dub_id='t81-resend';           -- 6
SELECT count() AS rows, uniqExact(event_key) AS keys FROM charges_raw FINAL
WHERE dub_id='t81-resend';                                                   -- 3  3
SELECT count() AS rows, sum(toInt64(round(cost_usd * 1000000000))) AS nanos
FROM charges WHERE dub_id='t81-resend';                                      -- 3  637800
```

## Effect on the workspace read

The workspace reader attaches a charge to a take by language, commit, segment and attempt. A charge from a discarded attempt now carries that attempt, so the reader has no take row to attach it to. The harness take carried 8 charges before the fix and 3 after. I did not change `internal/ledger/workspace.go`, which is outside the allowed paths. The charges view and the covers sentence stay correct.

## Re-render path

`internal/api/rerender.go` builds the run take for a corrected line and does not set `AttemptCharges`. That file is outside the allowed paths. `persist` therefore attributes a re-render's charges to the recorded take's attempt. A re-render that needs more than one attempt can still collapse two identical calls. Closing that path needs `internal/api/rerender.go`.
