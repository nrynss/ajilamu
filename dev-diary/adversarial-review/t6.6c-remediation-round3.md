## Why each key is unique by construction

The wire `Take` carries no commit or turn identity. Two takes can agree on every wire field,
because a second run reuses the per-dub work directory and the recorded take file. So a content
field alone can repeat. The array position is the only value unique inside one each block.

- `+page.svelte:1040` iterates the whole `takes` array. Position runs from 0 to n minus 1 and
  cannot repeat.
- `Speaker.svelte:165` iterates the same whole array, so position is unique there too.
- `DetailsTab.svelte:89` iterates `line?.takes ?? []`. Position is unique inside that block.
- `Track.svelte:79` iterates `takes.slice(0, -1)`. The slice drops the active take and holds at
  most n minus 1 elements. Position is the index inside that slice, so it stays unique even when
  two ghost takes share one file. The active take renders outside the each block, so it needs no
  key.

A reorder changes the keys. Svelte then recreates the nodes, which cannot mis-associate a row
with another row's content.
