### Whole-pass attribution

`Persist` rewrites each whole-pass charge onto the first rendered take in `attributeWholePass`.
The charge row then carries that take's minted id, the run commit id, and that take's segment
index and attempt. The `charges` view keys the ancestry sum on `commit_id`, so the run commit's
ancestry sum includes the whole-pass cost. Without the rewrite the row would carry an empty commit
id and the ancestry sum would exclude it, which the T4.5 probe measured. I judge the decision
honest for the cost total, and I note it overstates the first take's own cost.

## What I did not file

- **`Shutdown` swallows a run wait timeout.** `runRegistry.wait` returns silently when the context
  expires, so `Shutdown` can return nil while a run that ignores its context still runs. The spec
  asks for a bounded wait, and I measured that bound. I did not file it because the contract
  permits the abandoned wait.
- **The charge provider is the Gemini model for every charge.** `newRunRecorder` passes
  `cfg.GeminiModel` as `ChargeProvider`, so a synthesis row names a Gemini model.
  `ledger.TakeAttempt` carries one provider per take, and no task names a provider value, so I
  did not file it.
- **Runs are serialized across dubs.** `pipelineRunner.mu` holds for a whole run, so a run for one
  dub waits for a run of another dub. The adapter documents this as the charge router decision, so
  I treat it as deliberate.
- **The claim of twenty-four tests.** I count twenty-three new test functions across the four
  files. A count is not a code defect.
- **`FlaggedSegments` is not persisted.** The ledger has no flagged column, and no task asks for
  one.
- **Charges for a line with no take file are dropped.** `pipelineRunResult` classifies them as
  owned and then skips the line. The fit loop always gives a flagged line a chosen take, so the
  path is unreachable today.
- **A connection leak on a partial adapter build.** `newPipelineRunner` can leak a Gemini client
  when the TTS constructor fails after it. I could not prove the failure order, so I did not file
  it.
