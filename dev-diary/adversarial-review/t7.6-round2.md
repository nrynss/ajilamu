## Scope and Evidence

### Observers

The logging observer is `/tmp/t76r2/proxy.py`, a Python `ThreadingHTTPServer` that forwards each
request to the Go binary. It records the method, the path, the upstream status, and the byte
count. It writes the upstream line before it relays, so a client that closes early cannot hide
the request.

The CDP observer is `/tmp/t76r2/cdp.mjs`, a Node script on the built-in `WebSocket`. It attaches
to the page target, enables `Network`, navigates, and collects events.

The install observer is npm 12.0.2 with an empty cache directory. The browser is
`google-chrome-stable` 152.0.7977.82.

### Round one finding 1, the headless favicon

I built both frontends from source in `/tmp/t76r2/repo/web`. The pre-fix build uses HEAD's
`app.html` with no icon link. The fixed build uses the working tree's `app.html` with the data
URI link. Both builds came from `npm run build`. The fixed `index.html` holds one `rel="icon"`
link. The pre-fix `index.html` holds none.

The binary at `/tmp/t76r2/ajilamu` served each build through `AJILAMU_FRONTEND_DIR`. The proxy
listened on 18090 and forwarded to 18092. Each Chrome run used a fresh profile and an empty disk
cache.

The proxy observed the pre-fix build.

| Mode | Proxy requests | 404 | Favicon line |
|---|---:|---:|---|
| `--headless --dump-dom` | 11 | 1 | `GET /favicon.ico -> 404 Not Found (19 bytes)` |
| `--headless=new --dump-dom` | 11 | 1 | same |
| `--headless=old --dump-dom` | 11 | 1 | same |
| `--headless --screenshot` | 14 | 1 | same |
| `--headless=new --screenshot` | 15 | 1 | same |

The CDP client then attached to a page target and navigated to the proxy. It recorded 16 network
requests. One was the favicon. The events were
`Network.requestWillBeSent GET http://127.0.0.1:18090/favicon.ico type=Other` and
`Network.responseReceived 404` for the same request.

The proxy then observed the fixed build.

| Mode | Proxy requests | Favicon requests |
|---|---:|---:|
| `--headless --dump-dom` | 10 | 0 |
| `--headless=new --dump-dom` | 10 | 0 |
| `--headless=old --dump-dom` | 10 | 0 |
| `--headless --screenshot` | 14 | 0 |
| `--headless=new --screenshot` | 14 | 0 |

The CDP client on the fixed build recorded 15 network requests and zero favicon events. I decoded
the data URI and parsed the SVG with `xml.dom.minidom`. The root is `svg` in the SVG namespace.

Headless Chrome fetches the favicon in every mode. The proxy sees the request. The page-level CDP
client sees the request and the 404 response. The fixed build asks for no favicon.
