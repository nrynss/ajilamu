## What I did not file

- The `probeResponseBudget` value is unpinned. A mutation setting it to 3 seconds survived every
  shipped test. The suite pins the budget mechanism, because a 250ms budget reports waking, but no
  test pins the 15 second value. I did not file this because a numeric default pin needs either a
  constant assertion or a multi-second test, and the codebase pins no other numeric default. Round 1
  accepted wiring-only coverage for the dial timeout, so this row matches that standard.
- The connected flag is unpinned against a real dial timeout. A mutation that sets the flag on every
  connect attempt survived, because the 1ns dial fails before `ConnectDone` fires. With that mutation
  a SYN-dropping host reports waking instead of unreachable. The shipped code is correct, and my
  SYN-drop pins of 701ms and 2.002s both report unreachable. I did not file a defect because the
  required dial-timeout mutation is killed and no shipped-code path misclassifies.
- The T7.2b block still reads `status: claimed:orchestrator` and describes the retired
  `clickHouseProbeClient` at 3 seconds. Both belong to the orchestrator, who owns amendment.
- The two test packages duplicate four helpers. The package split forces the duplication, and round
  1 recorded the same observation.
- `probeDialTimeout` has no test that reads the shipped 2 second value. Only the wiring is pinned.
  This matches the treatment of `probeResponseBudget` above.
