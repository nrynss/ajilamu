## 1. Concurrent refresh

`go test -race -count=1 -run TestConcurrentRefreshBuildsOneClient -v ./internal/tts`

```
=== RUN   TestConcurrentRefreshBuildsOneClient
    catalog_test.go:279: client builds = 1, ListVoices calls = 8
--- PASS: TestConcurrentRefreshBuildsOneClient (0.00s)
PASS
ok  	github.com/nrynss/ajilamu/internal/tts	1.015s
```

Eight goroutines refresh at once. The build runs once and every caller shares the one
client. Each caller still issues its own `voices.list`, so the count is eight. I chose not
to coalesce refreshes. A shared fetch would let one caller's cancellation fail another
caller's refresh.

Mutation. I mapped the package through `go test -overlay` to a copy with the re-check
deleted. The same test logged `client builds = 8, ListVoices calls = 8` and failed with
`client builds = 8, want 1`. The repository file stayed untouched.
