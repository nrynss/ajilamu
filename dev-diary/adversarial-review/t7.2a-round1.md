### Done condition one: one helper builds every ClickHouse read request

Measured, not inferred. A repository search in `internal/ledger` for `query.Set(`,
`requestURL :=`, and `http.NewRequestWithContext` shows two request builders. `Client.send` at `client.go:196` is the write
path and issues an INSERT. `queryClickHouse` at `client.go:221` is the read path. All four
readers call it: `TimelineAt` and `branchCost` in `history.go`, `commitByID` in `commits.go`,
and `durationPriorStats` in `priors.go`. `postClickHouse` has no Go definition.

I exclude two paths from the done condition, with reasons.

- `internal/api/server.go:162` `probeClickHouse` sends an unauthenticated `GET /ping`. It
  carries no query and decodes no JSON. It is a liveness probe, not a data read, and it
  needs neither read setting. It also lives outside the helper's package.
- `Client.send` at `client.go:196` is the durable write path. The quoting setting shapes read
  output, and the depth setting caps a recursive read. Neither applies to an INSERT.

### Done condition two: an independent stand-in

I built `internal/ledger/zz_review_standin_test.go` in the scratch copy. It does not reuse the
new test. It matches statements by substring, uses its own payloads, and quotes every 64-bit
integer unless the request carries `output_format_json_quote_64bit_integers=0`.

`TestReviewStandInDiscriminates` sends a raw request with no pin and asserts the quoted body
fails to decode into `storedCommit`. `TestReviewReadersDecodeQuotedShape` drives `TimelineAt`,
`commitByID`, `durationPriorStats`, and `branchCost` and asserts each decodes. Both pass.

### Done condition three: no reader pins on its own

Measured. A repository search in `internal/ledger` for `query.Set(` shows the two setting names only in
`client.go`. The readers in `commits.go`, `history.go`, and `priors.go` contain no `query.Set`.

`TestOnlyClientPinsServerSettings` is not vacuous. It reads seven non-test files and fails if
any names either setting. Probe P1 confirms it has teeth. Mutation M8 confirms a reader can
still pin by string concatenation and pass. I judge the guard acceptable. It catches the
literal copy that caused this bug, and an AST-based guard demands rigor the repository does
not use elsewhere. See `What I did not file`.

### Regression measurements

The stand-in drives all four readers through the helper. Each call returns the plain shape and
decodes. Mutation M0 confirms the baseline is green. The readers keep parameter binding, EOF as
not found for `commitByID`, the no-row error for `durationPriorStats`, the non-2xx error shape,
the mismatched `commit_id` guard, and basic auth. The helper sets the auth header and closes the
body on a non-2xx response. `commitByID` and `durationPriorStats` keep their own EOF and
`commit_id` checks after the helper returns.

## What I did not file

- **Source-text guard limits.** `TestOnlyClientPinsServerSettings` is a text scan. P1 shows a
  comment naming the setting in a reader file fails it. M8 shows a concatenated pin passes it.
  I judge both acceptable. The guard catches the literal copy that caused this bug, and an
  AST-based guard is more rigor than this repository uses.
- **Error prefix change.** `commitByID` and `durationPriorStats` now return the helper wording
  instead of `parent lookup` and `duration prior query`. No test asserts the old text. The
  regression list in the task does not name it.
- **Depth pin on non-recursive reads.** The helper pins `max_recursive_cte_evaluation_depth`
  on `selectCommit` and `selectDurationPrior`. Those statements walk no recursive CTE. The
  setting is harmless there, and T4.5 measured Cloud accepting it.
- **Future readers outside the package.** T7.2c and T7.3 own `internal/api`, not
  `internal/ledger`. They call the exported ledger methods, which route through the helper.
  They cannot call the unexported helper. This is not a defect for this task.
- **Historical record.** `dev-diary/adversarial-review/t4.5-live-probe.md` also names
  `postClickHouse`. It is a past review record, so it stays as written.
