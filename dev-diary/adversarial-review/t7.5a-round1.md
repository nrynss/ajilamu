### Project metadata

`ProjectMetadata` returns `api.DubSummary`. It sets `ID`, `Languages`, `CreatedAt`, and
`UpdatedAt`. It leaves `Title`, `Readiness`, and `TotalNanodollars` empty. `api.DubSummary` has
no `SourceLanguage` field, so that part of the brief does not apply. `SourceLanguage` belongs to
`api.Dub` and no non-test code sets it.

The read is honest. Its comment and the handoff both say the ledger stores no title and no
readiness, and both leave them for the route. The handoff does not name `TotalNanodollars`, so I
measured it empty and report that here. No caller exists yet. `api.DubSummary` is the index row
type, and `api.IndexHandler` builds its own from upload records. The T7.5 route is the first
consumer of this read.

### Language list

`Languages` groups `takes` by language. A dub with no takes returns an empty list. `WorkspaceTakes`
returns no track for that dub. The wire `Dub.Languages` is `[]LanguageTrack`, so an empty list is
valid and the page renders its pending state. The read's comment states the empty case, so the
behaviour is deliberate. I did not file it.

### Charge split

The split cannot double count. Statement 2 selects only `kind IN ('translate', 'synthesize')`.
Statement 3 selects only `kind = 'segment'`. The two sets are disjoint. Statement 4 sums every
`charges` row once through the materialized `cost_usd`. The measured total on my dataset was the
exact sum of the itemized rows plus the whole-pass row, `1572100` nanodollars. The first take's
itemized charges did not carry the segment row, because statement 2 excludes it.

### Settings

`queryClickHouse` in `internal/ledger/client.go` sets `output_format_json_quote_64bit_integers=0`
and `max_recursive_cte_evaluation_depth=5000` on every request. All six workspace statements

`sql/schema.sql` names the depth setting in an explanatory comment, which predates this task.
`TestOnlyClientPinsServerSettings` scans the ledger package and passes.

## Findings

| # | Sev | Where | What | Pin | Mutation |
|---|---|---|---|---|---|
| 1 | H | `internal/ledger/workspace.go:361-372` | `buildLanguageTracks` builds each `api.Take` with no `Charges` slice and appends charges only when the take owns some. A take with no itemized charge therefore carries a nil slice. The `api.Take.Charges` JSON tag has no `omitempty`, so the wire payload carries `"charges":null` instead of the `[]` that `testdata/wire/take.json` and `web/src/lib/types.ts` declare. The frontend breaks on that shape. `DetailsTab.svelte:15` flattens each take's charges and line 16 reduces the result, so a null element breaks the reduce. `DetailsTab.svelte:77` iterates the same null in a keyed each. A stretched take is exactly this case. The fixture records the two atempo takes with `"charges":[]`, and its total note says the stretches cost nothing. `internal/fit/rewrite.go` bills no call for a local atempo pass. The author already initializes `Lines` to `[]api.Line{}` on line 345, so the nil `Charges` breaks the file's own convention. | `TestReviewNilChargesMarshalNull` in `/tmp/t75a-scratch/internal/ledger/zz_review_measure_test.go`. It drives `WorkspaceTakes` over one charge-less take. It logged `take.Charges nil=true` and the marshalled take `{"file":"b.wav",...,"charges":null}`. `testdata/wire/take.json` carries `"charges":[]` for the same charge-less shape. | M2 added `Charges: []api.Charge{}` to the take literal in the scratch copy. The same test then logged `"charges":[]`. Reverting the line restores null. The shipped `TestWorkspaceTakesGroupsAndOrders` builds a segment-two take with no charges and never asserts its `Charges`, so the suite stays green either way. |

The fix initializes the slice in the take literal.

```suggestion
		take := api.Take{
			Charges: []api.Charge{},
			File:    row.AudioPath,
```

## What I did not file

- **`Take.StretchFactorMilli` stays zero.** The read never sets it, and the handoff records that
  choice. The ledger has no dedicated ratio column. However `repair_detail` carries
  `atempo stretch applied at ratio %.4f` from `internal/fit/rewrite.go:390`, and the read does not
  select that column. `LengthBar.svelte:149` and `DetailsTab.svelte:28` consume the wire field. I
  did not file it because the task names fit and charges, and the handoff records the zero. A
  later task can recover the ratio from `repair_detail`.
- **The ORDER BY tie-breakers are incomplete.** Statements 2 and 3 and their Go comparators omit
  the fields that distinguish two charge rows of one take and unit. `event_key` covers provider,
  units, and price, so two such rows can coexist. Their order is then unspecified. I could not
  measure a user-visible reorder, so I did not file it. `selectCommitHistory` orders on a total
  key, so a later round may want the same here.
- **A take with two charges of one kind breaks a keyed each.** A translate call bills prompt and
  candidate tokens as two rows, and `DetailsTab.svelte:77` keys on `take.file-charge.kind`. That
  key sits in T5 code rather than this task.
- **The stand-in cannot validate a column name.** The shipped test serves canned JSON, so a typo
  in a column would pass. The handoff's separate ClickHouse run is the pin for that, and I re-ran
  it.
- **A dub with a commit and no rendered take reports no language.** The read documents the empty
  case, so I treat it as deliberate.
