**Verdict: REMEDIATE.** Counts: **C 0, H 0, M 1, L 0.**

The remediation fixes round one M1 and M2. I re-measured both and pinned each by
mutation. The timeline now carries the ghost shapes in the lanes. Both panels name the

## Findings

| Where | What | Pin | Mutation |
|---|---|---|---|
| `web/src/lib/edit/Speaker.svelte:112-123` and `web/src/routes/d/[id]/+page.svelte:280` | **M.** `confirm()` awaits `onchange` and then writes `note` from the reply. It never checks that the selected line is still the one it started on. The page's `handleSpeakerChange` writes `lineNote` from the reply with the same gap. A creator who confirms a speaker change and selects another line before the 201 lands sees the old line's sentence on the new line. | I set the stand-in reply delay to 1500 ms. I confirmed the speaker change on line 3 and immediately selected line 1. The line 1 Speaker panel read `Line 3 re-rendered as take seg_3_try3.wav.` and the line 1 take strip read the same. The panel label read `Line 1` and the header read `Suni Williams`. | Removing the id guard restores the leak. `Text.svelte:132` already guards the same case with `if (segment.id !== targetSegment.id)`, so the fix follows the existing idiom. |

The two fixes:

```svelte
async function confirm(): Promise<void> {
  const choice = pendingSpeaker
  const take = estimateTake
  const targetSegment = segment
  ...
  const result = await onchange({
    segment: next,
    previousSpeaker: segment.speaker,
    speaker: choice,
    estimatedNanodollars,
    takeFile: take.file
  })
  if (segment.id !== targetSegment.id) {
    pendingSpeaker = undefined
    return
  }
  if ("error" in result) {
    error = result.error
    return
  }
  note = result.sentence || `Line ${segment.id} re-rendered as ${result.take.file}.`
```

```ts
const reply = await rerenderLine({
  segmentId: change.segment.id,
  language: activeLanguage,
  speaker: change.speaker
})
if (selectedSegmentId === change.segment.id) {
  lineNote = "error" in reply ? reply.error : reply.sentence
}
return reply
```
