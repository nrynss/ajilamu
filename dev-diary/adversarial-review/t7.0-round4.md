## Residue Against Findings 1 Through 10

**Finding 1, closed.** `.gitignore` line 8 reads `/ajilamu`. The anchored rule keeps `cmd/ajilamu/main.go` tracked while ignoring the root binary. A clean clone receives the entrypoint source.

**Finding 2, closed.** I ran the binary under `env -i` with `PORT=48101`. `kill -INT` gave exit code 0. On port 48102 `kill -TERM` gave exit code 0. Neither log contained `ledger client is nil`.

**Finding 3, closed.** On port 48103 with `AJILAMU_DATA_DIR` set to a temporary directory, a multipart POST to `/api/dubs/new` with video, music, and `language=es` returned status 201 with `Content-Type: application/json`. The uploaded files were stored on disk under `uploads/<id>/` at mode 0600 with matching byte counts.

**Finding 4, closed.** `.gitignore` line 9 reads `/data/`. A default-data upload wrote files into `data/uploads/`, and Git ignored the entire `/data/` directory.

**Finding 5, closed.** On port 48104, unmatched API paths and methods (`GET /api/dubs/new`, `POST /api/dubs`, `GET /api/config`, `POST /api/healthz`, `GET /api/nonexistent`) each returned status 404 with `Content-Type: text/plain; charset=utf-8` and body `404 page not found`. Valid API routes (`GET /api/healthz`, `GET /api/dubs`) returned status 200 JSON in the same run.

**Finding 6, closed.** `Server.Shutdown` drains HTTP connections while `Server.FlushLedger` flushes ledger events on an independent deadline. On port 48105 with ClickHouse environment variables set and a fake ClickHouse ping server running on port 48199, I initiated a slow download (`curl --limit-rate 100k` against `/clip.mp4`) and sent SIGTERM after one second. The process drained, flushed the ledger, logged `ledger flush finished`, and exited with status 0. On port 48106 against a dead ClickHouse port 48198, SIGTERM flushed, logged flush failure with pending count details, and exited status 0 without losing queued events on disk.

**Finding 7, closed.** In a temporary directory containing only a `testdata` symlink, running the binary with `ENV=production` and all required credentials (`CLICKHOUSE_HOST`, `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD`, `GOOGLE_CLOUD_PROJECT`) exited immediately with status 1 and logged `ENV=production requires a frontend build: set AJILAMU_FRONTEND_DIR or run npm --prefix web run build`. Production refuses to boot in degraded mode without a build.

**Finding 8, closed.** Starting the binary from a foreign working directory with `AJILAMU_FRONTEND_DIR` pointing to a custom build directory served `/` with status 200 and returned the expected HTML body from that setting.

**Finding 9, closed.** On port 48109 with ClickHouse environment variables pointing to dead port 48197, `GET /api/ledger/ready` returned status 503 with body `ClickHouse did not answer a ping.`, while `/api/healthz` returned status 200. When pointing to a live ClickHouse ping server on port 48199, `/api/ledger/ready` returned status 200 with `{"status":"ready"}`.

**Finding 10, closed.** On port 48110, posting `voice_key` and `translation_key` to `POST /api/config` returned status 503 with body `Settings are unavailable.`, matching the unconfigured callback contract prior to T7.4a landing.
