## Contract notes, outside my seam

- **`charges.take_id` is now informational.** A reconnect that regenerates a take id
  can leave the surviving charge row carrying the fresh id. T4.2's cost rollups and the
  take panel should join on the stable identity columns, never on `take_id` alone. The
  file comments say this where the column and the sorting key are declared.
- **A dub wide charge names its pass's commit.** The segmentation charge carries the
  commit of the pass that billed it. Without that value a later re-segmentation pass
  would share the charge identity of the first one. The file comment says so, and
  `PHASE-4-ledger.md` T4.2 should record it.
- **Cloud writes macro arguments into `engine_full`.** A Cloud table created as
  `ReplacingMergeTree(ingested_at)` reports
  `SharedReplacingMergeTree('<path>', '<replica>', ingested_at)`. The guard therefore
  cuts the engine token before `PARTITION BY` and checks its end for the version column.
  Nobody should simplify that branch back to a whole-string equality.
- **`internal/cost/cost.go` declares `Charge.TakeID int` while `charges.take_id` is
  `String`.** Both files are frozen. T4.2 must bridge the two. Round 2 raised this and
  I repeat it so the bridge does not surprise T4.2.
- **T4.1 still needs its write contract written down in `PHASE-4-ledger.md`.** Writes
  name the `_raw` table and reads name the plain view. `take_id`, `charge_id` and
  `action_id` are informational, so the queue may generate them freely. A genuine
  repeat call must raise `attempt` when it repeats the take, the kind, the provider,
  the unit, the count and the price. I cannot edit `PHASE-4-ledger.md`.
