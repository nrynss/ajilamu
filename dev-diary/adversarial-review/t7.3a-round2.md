### Finding 1 detail

`takeFileUsable` checks only that the file is regular and non-empty.
A recorded take cut inside the 44-byte WAV header is non-empty and undecodable.
On the `InitialTake` path `RepairLine` calls `media.Duration`, which fails,
so the whole resumed run aborts with `ErrSourceUnreadable`.
On the replay path `reusableTake` returns nil and `repairSegment` returns the stored result,
so the run adopts the corrupt take with zero synth calls.
The production writer `writeTake` writes the payload once to the final path,
so a crash or a full disk during that write leaves such a partial file.
The new comment claims to reject an unreadable take, so the behaviour contradicts that contract.

The fix is to probe the take before the loop trusts the record.
`readSegmentRecord` already receives the segment and can receive the context.

```go
// takeFileUsable reports whether a recorded take holds audio the loop can measure.
// An empty, missing, unreadable, or undecodable file is not completed work.
func takeFileUsable(ctx context.Context, path string) bool {
	if path == "" {
		return false
	}
	info, err := os.Stat(path)
	if err != nil || !info.Mode().IsRegular() || info.Size() == 0 {
		return false
	}
	if _, err := media.Duration(ctx, path); err != nil {
		return false
	}
	return true
}
```

The caller then reads `if !takeFileUsable(ctx, rec.Result.ChosenTake.File) {`.
`readSegmentRecord` takes `ctx context.Context` as its first parameter,
and `repairSegment` passes its own context.

## What I did not file

- **Deleting the take file.** The removal is safe under the loop contract.
  The loop writes the record atomically, the record names the loop's own take,
  and that path sits under the work directory. The file is unusable when the loop removes it.
  The one unsafe corner is a hand-edited record that names a path outside the work directory
  or an empty directory. I treat that as out of contract.
- **`os.Open` on a FIFO.** `takeFileUsable` opens the path before it checks the mode.
  A record that names a FIFO would block the run. A record never names a FIFO today.
  The suggested fix above uses `os.Stat` first, so it also closes this corner.
- **The resumed run reports zero cost for replayed lines.** Round 1 did not file it.
  The ledger holds the first run's charges, so the project counts each segment once.
- **A line interrupted mid-attempt with no record still aborts.** `TestR2LeftoverTakeNoRecord`
  measured `err=repair line 1: synthesize line 1 attempt 1: tts refuses to overwrite .../seg_1_try1.wav`
  and zero synth calls. The new removal is record-scoped, so it does not reach this case.
  Round 1 did not file it, and the Done-when stops after a completed take.
- **The record name does not carry the language.** One language per work directory is the
  existing contract, and take names collide across languages anyway.
- **The shipped tests leave three paths unpinned.** The language check, the segment check,
  and the `InitialTake` path survive a mutation when only the shipped tests run.
  My pins catch all three. This is a coverage observation, not a defect.
