# T6.5c serve take audio: round 1

**Verdict: REMEDIATE.** Counts: **C 0, H 0, M 1, L 0.**

A real project's takes play from the served route. The fixture path is unchanged. A
name-based traversal attempt is refused. One defect remains. The handler serves bytes
outside the storage root when a symlink inside the root points out. The task requires a
path outside the storage root to fail. That requirement does not hold.

## Findings

| Where | What | Pin | Mutation |
|---|---|---|---|
| `internal/api/takes.go:46-51`, with `:77-83` | **M.** `pathInside` compares the joined path with the storage root through `filepath.Rel` and never resolves a symlink. `os.Open` follows a symlink in the work directory. A link inside the root that points outside therefore serves the outside file. The handler comment claims the resolved path stays inside the root. A traversal attempt by name is refused. A symlink defeats the check. | Against the real `cmd/ajilamu` on port 8831 with a real project under `AJILAMU_DATA_DIR`, I placed `escape.wav` as a link to `/tmp/t65c-review/outside/secret.wav` and `passwd.wav` as a link to `/etc/passwd` inside `uploads/t65clive/work/ml-IN`. `GET /api/dubs/t65clive/takes/ml-IN/escape.wav` answered 200 with `Content-Length: 22` and the body `SECRET-OUTSIDE-CONTENT`. `GET /api/dubs/t65clive/takes/ml-IN/passwd.wav` answered 200 with 2168 bytes, and the body began `root:x:0:0::/root:/usr/bin/bash`. | Replace the `pathInside` check and `os.Open(path)` with a relative-path check and `os.OpenInRoot(root, relative)`. The symlink pin flips from 200 to 404. The real take still answers 200 and the range still answers 206. The four existing `TestTakeAudio` tests still pass, so they never pinned the symlink case. |

The concrete fix resolves the path under the root and opens it there:

```go
		target := filepath.Join(runWorkDirFor(root, dubID, language), name)
		relative, err := filepath.Rel(root, target)
		if err != nil || relative == ".." || strings.HasPrefix(relative, ".."+string(filepath.Separator)) {
			http.NotFound(w, r)
			return
		}
		file, err := os.OpenInRoot(root, relative)
		if err != nil {
			http.NotFound(w, r)
			return
		}
```

`os.OpenInRoot` refuses a path that escapes the root through a symlink. Go 1.27.1 in
`go.mod` provides it. I built this fix in a `/tmp` copy and measured both links at 404.

## Handoff check

The handoff matches every measurement I repeated. The 200, the content type, the byte
count and the `ffprobe` duration match. The range answer matches. The three name escapes
and the raw dot dot match. The fixture bundle matches. Both browser controls match. Both
commands match. `cmd/ajilamu/main.go` needed no change, and line 113 passes `uploadDir`
as `StorageDir`.

Three handoff gaps. First, the handoff does not probe a symlink. Its traversal list
covers name-based escapes only. The claim that the joined path stays inside the root
holds only lexically. Second, the handoff says the handler "rejects a separator, a dot,
or a double dot". The code rejects a name that is exactly `.` or `..`, and any name with
`/` or `\`. A name with an interior dot, such as `seg_3_try1.wav`, is accepted. The
behavior matches the intent, and the wording is loose. Third, the handoff says "the page
never sends the server path to the browser". The ledger payload does send the absolute
path, and the DOM shows it in `data-take-file`. The audio URL carries only the basename.

## Residue

No prior T6.5c round exists, so this round carries no finding.

The route serves any regular file in the work directory, not only takes. I fetched
`seg_3_result.json` and got 200 with the record body. The unauthenticated workspace route
already exposes similar data, so I do not file it. The author may want to restrict the
name to a take shape.

`playTake` swallows a failed playback. A 404 or a 503 leaves no note. The picture
playback uses the same catch. This predates the patch and does not block.

The language resolver prefers a directory that holds a resume record. A take in a
directory with no record is unreachable. `runWorkDirFor` owns that behavior, not this
patch.

## Done condition

The done condition reads: a real project's takes play from the served route, the fixture
path is unchanged, and a traversal attempt is refused.

The first two clauses hold. The third clause holds for a name-based traversal attempt. A
symlink inside the storage root that points outside is served with 200, so a path outside
the storage root does not fail. The task's storage-root requirement therefore does not
hold, and I set the verdict REMEDIATE.
