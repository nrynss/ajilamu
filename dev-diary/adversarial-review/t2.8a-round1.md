### M1: The source language name is unpinned for a non-English source

`translatePrompt` reads `SourceLanguageName` and writes it into two slots of the known-source
body. The contract requires the prompt to name the source language when the request carries one.
Every test in `internal/gemini` passes `"English"`. That value matches the old hardcoded wording,
so the tests cannot separate the new field from a constant.

I mutated `translate.go` line 128 to hardcode `"English"` in both source slots and to keep
`source` only in the emptiness check. The file compiled. All 20 tests passed, including
`TestTranslatePromptNamesTargetLanguage`. The Spanish target prompt in that test still said
`Translate this English dialogue line` and `Original English:`, because the source name was the
hardcoded one.

The trigger is a pipeline built for a non-English source, such as Spanish audio into Malayalam.
The impact is a silent wrong-language prompt. Add a case with a non-English source name.

```suggestion
	req := TranslateRequest{
		SegmentID:          8,
		Text:               goldenText,
		TargetSlot:         7110 * time.Millisecond,
		Emotion:            "Explanatory",
		TargetLanguageName: "Malayalam",
		SourceLanguageName: "Spanish",
	}
```

The case must assert `Translate this Spanish dialogue line` and `Original Spanish:` in the prompt.

### M2: The Malayalam prompt no longer matches the proven body

The old body read `Translate this English dialogue line into natural spoken Malayalam script
(മലയാളം):`. The new template reads `Translate this %s dialogue line into natural spoken %s:`.
For a Malayalam target the only difference is the dropped ` script (മലയാളം)` suffix. My probe
logged the full new prompt and the rest of the body is identical, including `Original English:`,
the constraint sentence and `Respond with strictly the translated Malayalam text.`

The T2.8a done condition says the Malayalam fixture behaviour is unchanged. The live evidence in
the T2.2 handoff recorded prompt token counts of 107, 99 and 110 against the proven body. The
shipped prompt is no longer that body. The test that used to pin the proven bytes was rewritten
in the same patch, so the suite cannot show the change.

The comment on the template still says the wording follows the proven body in
`tools/validate_pipeline.py`. That claim is now false for Malayalam.

No exact replacement exists while the request carries one target name. The proven body used
`Malayalam script (മലയാളം)` in the opening slot and `Malayalam` in the closing slot. The author
must choose. Keep the proven opening wording, or record the change and its lost live evidence.

### L1: Two assertions in the rejection test cannot fail

`TestNewSynthesizerRejectsBadLanguageBeforeAnyCall` checks that the rejected constructor made no
client call and recorded no charge. `NewSynthesizer` returns before it touches the client and it
never adds a charge. Both assertions hold for every possible error path. They add no coverage.

```suggestion
	for _, code := range []string{"", "spanish", "es_ES"} {
		if _, err := NewSynthesizer(testConfig(), code, ledger, cost.DefaultRateCard(), client); err == nil {
			t.Errorf("NewSynthesizer(%q) = nil error, want rejection", code)
		}
	}
```
