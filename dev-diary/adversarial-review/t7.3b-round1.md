## What I did not file

- **The attempts counter resets after a successful open.** A server that answers 200 and closes
  the body at once makes the client reconnect every 500 ms with no growing delay and no ceiling.
  I measured six fetches in three seconds with gaps of 502 to 508 ms. The code comment and the
  claim both say six failed attempts end the watch, so I read the reset as deliberate. I measured
  the ceiling with reconnects that fail to open.
- **The start control renders only for fixture ids.** The page sets `dub` to undefined for a real
  id, so no workspace and no button appear. That gate predates this patch, and T7.5a owns the real
  workspace payload. The patch does not create the gate, so I did not file it.
- **A reload during an active run shows the start button until the user clicks it.** The click
  answers 409 and attaches, which the claim names as the attach path. Auto-subscribing on mount
  would show the events 404 sentence for every idle project. I treat the click gate as deliberate.
- **The start button keeps the user agent padding and measures 22 px tall.** WCAG 2.1 AA has no
  target size rule, and the contrast passes. I judge this polish, not a defect.
- **Chrome retried my severed first event request internally.** The browser therefore cannot
  measure the client rule that a first contact never retries. Chrome reissued the request before
  any response headers, so the client saw a live stream. The module pin covers the rule.
- **The favicon 404 and the history 503.** Both predate this diff and neither owned file touches
  their cause. I did not file them.
